# Official Workspace Browser integration

This integration derives at build time from four individually version- and SHA-256-gated MIT-licensed DeepSeek Harness packages: `@deepseek-ai/dsh-client-ui-workspace@0.2.2-rc.1`, `0.2.1-rc.5`, `0.1.6-alpha.2`, and `0.1.7-rc.2`. The two modern entries are separate derivatives, not one artifact tolerant of both Hosts: decoration is compiled in at build time and binds one official Client, and `0.2.1` never provided the `contextMenus` service that the `0.2.2` derivative requests. `src/host-compat.ts` therefore splits the modern line on the patch position - `0.2.0.x`/`0.2.1.x` select the rc.5 derivative, `0.2.2.x` and later the rc.1 one. The two narrowed `cwd` seams are one shared seam definition serving both derivatives. They are build-time aliases, not private runtime copies of Host singleton packages.

The public Slot ledger can elect a lower-priority Browser, but a wrapper entry cannot inherit the original entry's child-slot authorization: omitting `children` removes the `renderSlot` seat, while repeating `children` redeclares `sidebar.workspaces.directoryFlow`. Therefore `cordis.patch.yml` conditionally disables the original loader row only while this plugin's Host provider marker is active and its entry is enabled. `src/workspace-provider-lifecycle.ts` reconciles that selection through public Loader entry update/refresh/init operations, including late Include activation and disable-list replay, without persisting a disabled flag. On deactivation the marker is explicitly released before the official row is restored; Cordis 4.1.0 runs effect cleanup concurrently, so registration order does not guarantee this. Cordis 4.1.0 returns `Object.create(fiber)` from `ctx.plugin()` and Loader stores that wrapper on `entry.fiber`, so the reference is no longer identical to `ctx.fiber` but inherits from it — the lifecycle compares both forms. Loader 1.1.0 keeps disposed fiber references: disable waits on the fiber, and restore uses public `init()` for a dead generation. Only the matching replacement entry/fiber reference is withdrawn on disposal or failed activation, with the owning `internal/plugin` event notifying the registry; successful same-fiber restarts retain the reference. Explicit user overrides are not replaced and no configuration is persisted. The matching `scripts/workspace-sidebar-upstream*.mjs` embeds each pinned official Client factory. The proxy preserves its official declaration tree, WorkspacePicker, locale dictionaries, stores, and directory-flow behavior. It replaces the Browser data projection and applies exact, fail-closed source seams for Managed owner identity, status, unsafe row operations and new-generation service shortcuts (fail-closed until topology is verified); canonical Session titles and ordinary Local rows remain official behavior. The newer derivatives deliberately preserve the official Browser's changed Hook/Slot contracts rather than transplanting the rc.1 Browser. The rc.2 branch registers its additional menu/action, search and overlay seats under the official authorization tree. On managed rows the registration proxy preserves the official pin, rename and archive entries (including their inverse actions, dialogs and hover controls), even while topology is unverified; these operations do not change owner identity or Workspace membership. Fork and unclassified entries remain guarded. Alpha retains its native menu and filters only fork for managed rows. Service-level guards block owner forks and new Sessions in managed Workspaces, not rename/archive; all derivatives capture the guard on each `uiWorkspace` instance at construction because Cordis derives a Context that does not retain the registration proxy's virtual `get` override. Ordinary rows retain their official actions once topology is verified. The Host-resolved `dsh-agent` package version selects exactly one derivative via strict Remote topology; unknown generations keep the official provider instead of mounting a guessed replacement.

The upstream version and compiled Client SHA-256 are hard gates for each variant. All four follow the split Client architecture: Cordis owns the Context, API Session/Workspace Controllers own list snapshots, and `dsh-client-store` owns browser-local viewing state. `scripts/check-workspace-sidebar-version.mjs`, `scripts/check-publish.mjs`, focused compatibility tests, and a real Chromium DOM/Host probe must all pass before claiming a runtime compatibility combination. The previous 0.2.0-rc.2 variant was browser-smoked on an isolated source Host (including a managed blank Session and badge spacing); that historical result does not accept the current 0.2.2-rc.1 derivative. The current unreleased source (plugin version 0.14.0) passes fresh typecheck, build, source/hash and publish gates plus the full suite (4 platform-conditional skips), including real Loader/registry regressions. **0.2.2-rc.1 was browser-smoked on an isolated source Host this round**: on the 0.2.2-rc.1 source tree, a `DSH_HOME=E:/tmp/dsh-rc1-home` Web profile with the plugin linked in loaded both the decorate branch (official Browser present, `decorated sidebar registered`, no page error) and the takeover branch (official Browser removed from the module graph, sidebar rendered). The takeover branch exposed a real defect the unit tests could not see: `apply` reads `ctx.remoteAccess` as a property, so the registration proxy must answer that form too, not only `ctx.get('remoteAccess')`. **0.2.1-rc.5 was browser-smoked on its own isolated Host this round** (`E:/tmp/dsh-rc5-host` running the published 0.2.1-rc.5 CLI, `DSH_HOME=E:/tmp/dsh-rc5-home`, profile `probe5`): the decorate branch reported `topology resolved modern-rc5` with no page error, and the takeover branch rendered the sidebar with no page error. AI conversation, review/delivery/cleanup and desktop end-to-end remain unaccepted. Alpha.2 has not yet been browser-smoked on an isolated Host. See the repository `NOTICE` for attribution.

Focused regressions execute all three pinned Client factories against Cordis to verify owner rename/archive/unarchive callbacks, native stop-and-archive options, ordinary fork forwarding, and fail-closed owner/new-session guards before and after topology verification. These callback tests do not replace a real Host UI smoke for menu rendering, keyboard bindings or running-work confirmation.
