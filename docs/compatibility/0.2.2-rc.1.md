## rc.5 → rc.1 source differences and seam survival

Unlike rc.3 / rc.4 / rc.5, this bump is a **real source change**: the official Workspace Client grows from 232824 to 284999 bytes and its compiled SHA-256 changes from `9c2c17a6…6544` to `bb31f7870381f737b2cb45db4c7911a08a4949856bc86b648a10d3e85a3e9f89`. Three upstream contract changes matter to this plugin:

1. **Built-in Session actions move off the slot ledger.** rc.5 registered `{ name: 'sidebar.workspaces.session.menu.item', id: 'session-id', order: 450 }`; rc.1 no longer contains the string `session-id` at all and registers `ctx.contextMenus.register({ id: 'session.<id>', target: 'session', order, observe, resolve })` for pin(100)/rename(200)/fork(300)/id(450)/archive(600). The plugin's owner-safe set therefore loses its now-dead `'session-id'` entry, and the `contextMenuContributions` assertion replaces the descriptor assertion in the focused tests.
2. **Row components gain `contextMenus` hooks, and the context gains the service.** rc.1 `SessionNodeItem` takes `useContextMenu`, `useContextMenuTarget`, `useSessionAccess`, `openSessionMenu` and `home`, and the official `inject` list is 10 entries with `contextMenus` first. The plugin inherits it, because `src/client/console-remote/index.ts` filters `officialWorkspaceInject` rather than hard-coding a list.
3. **`apply` reads `ctx.remoteAccess` as a property, not via `ctx.get`.** `ctx.slots.provideRoot({ keyedHooks: { workspaceAccess: (workspaceId, action) => ctx.remoteAccess.source(...) } })` bypasses the service registry, so the registration proxy must answer both forms. Only the `get` form was answered before, which crashed the official row hook and surfaced as `slot entry crashed in 'sidebar.workspaces'`. This is the defect the isolated browser smoke caught; it is now covered by two regressions in `tests/client-workspace-sidebar-profile.test.ts`.

Two of the 38 decoration seams broke, both because rc.1 inserted a `cwd` field:

1. `session node metadata` — the old anchor ended at `updatedAt: s.updatedAt,` followed directly by the `pendingInteraction` spread, but rc.1 inserts `...s.cwd === void 0 || s.cwd === "" ? {} : { cwd: s.cwd },` between them. The anchor was narrowed to `archived: archived.has(s.id),\n\t\t\t\tupdatedAt: s.updatedAt,`, a prefix shared by rc.5 and rc.1, so one seam definition serves both derivatives; the plugin spread still lands after `updatedAt`.
2. `hover Worktree identity` — the old anchor carried `!node.blank` after the `displayTitle` children block, but rc.1 inserts a `hoverPath` div rendering `cwd` before it. The anchor was narrowed to `children: displayTitle(node, t)\n\t\t\t\t\t}),`, again shared with rc.5.

Narrowing the anchors does **not** make one artifact span both Host generations. A decoration is compiled in at build time against one pinned official Client, so the plugin ships two derivatives: `virtual:dsh-official-workspace-client-rc5` (from `@deepseek-ai/dsh-client-ui-workspace@0.2.1-rc.5`, SHA-256 `9c2c17a6…6544`) and `virtual:dsh-official-workspace-client` (from `0.2.2-rc.1`, SHA-256 `bb31f787…9f89`). `src/host-compat.ts` splits the modern line at the patch position — `0.2.0.x` / `0.2.1.x` → `modern-rc5`, `0.2.2.x` and later `0.2.x` → `modern-rc1` — and `src/client/console-remote/index.ts` applies the matching one. The rc.1 derivative declares `contextMenus` on its child fiber only, because 0.2.1 Hosts do not provide that service.

All eight required text seams reach the derived source: `__dshGitWorktreeManagedGuard`, `dshGitWorktree.managed`, `dshGitWorktree.state.working`, `managedWorktreeDecoration`, `ManagedWorktreeIdentity`, `__dshGitWorktreeProtected`, `__dshGitWorktree`, `data-managed-worktree`. `visibleSessionMenuItems` is absent from upstream on every generation because that identifier is introduced *by the plugin's own decoration*; its seam is `replaceIfPresent` and its absence is the expected, unchanged case.

Two dependency contracts also moved:

- **Cordis 4.1.0 changes fiber identity.** `ctx.plugin()` returns `Object.create(fiber)`, and Loader stores that wrapper on `entry.fiber`, so `entry.fiber === ctx.fiber` is false while `Object.getPrototypeOf(entry.fiber) === ctx.fiber` is true (4.0.5 stored the fiber itself). `src/workspace-provider-lifecycle.ts` compared by identity only, so a failed activation never cleared `entry.fiber` and the Web graph kept a dead plugin row. The comparison now accepts both forms.
- **Loader 1.1.0 replaces the `EntryTree.write()` persistence hook with `commit(change)`.** The lifecycle regression spied on `write` and failed with `Error: write does not exist`; it now spies on `commit`.

13. Tests — `contextMenus` stubs in the three client suites, `contextMenuContributions` assertions replacing `session-id` descriptors, `commit` instead of `write`, the new peer range in `host-compat.test.ts`, two new `remoteAccess` proxy regressions, and both modern variants in the actions/status suites.

## Not validated

- AI conversation and the complete review/preview/delivery/rollback/recovery/cleanup runtime lifecycle (no API key configured in the isolated profile)
- Managed-checkout creation and delivery end to end in the browser (the isolated Host ran outside a managed checkout, so the sidebar reported `not_git_repository`)
- Desktop end-to-end behaviour
- Release Git cleanliness, packaging and publishing
- The `alpha` (`0.1.6-alpha.2`) and `next` (`0.1.7-rc.2`) derivations: gated and tested, not browser-smoked

## Residual risks

- The decoration path still relies on exact text seams in the official compiled Client. rc.1 proved that a real upstream change breaks two of 38 anchors, so every upstream bump must re-run the version/SHA gate and the seam probe; a silent seam drift fails closed at build time, not at runtime.
- Two derivatives now ship, so `lib/client.js` grew from ~1.25 MB to ~1.48 MB. Every Host generation parses both; only one is applied.
- The modern split keys on the patch position (`0.2.2` and later → rc.1 derivative), which follows the `contextMenus` service boundary observed in the registry rather than a declared compatibility promise. If upstream back-ports that service into a `0.2.1` patch, or removes it from a later `0.2.2` release, `src/host-compat.ts` must be updated with the bytes that prove it.
- `ctx.remoteAccess` was read as a property by rc.1 while `ctx.get('remoteAccess')` still works. Both forms are answered now; if a future generation removes the property form, the stub branch (`{ source: () => ({}) }`) would silently serve a no-op service instead of failing loudly.
- Compatibility was exercised on Windows only. The macOS-only cases (newline-in-path identity reads, executable-bit resource preservation) did not run here.
- `pnpm-workspace.yaml`'s `minimumReleaseAgeExclude` list is maintained by hand per DSH release; a future bump that forgets it surfaces as an install-time minimum-release-age rejection rather than a silent version mix.
