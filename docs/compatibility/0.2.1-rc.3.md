## rc.2 → rc.3 source differences and seam survival

The official Workspace Client changed only its pre-session draft semantics between rc.2 (232668 bytes) and rc.3 (232824 bytes):

1. `whenDraftExists` (`"replace" | "keep"`) replaces the previous `clearPreviousDraft` boolean, defaulting to the old behaviour when unset (`draftOptions.whenDraftExists ?? (draftOptions.clearPreviousDraft === true ? "replace" : "keep") === "replace"`).
2. Blank-Session reuse additionally filters on the `agentPreset` projection value: `workspace.path && workspace.sessionIds.includes(id) && !archived.includes(id) && (options.agentPreset === void 0 || typeof listed !== "string" || listed === options.agentPreset)`.
3. The `openWorkspaceSession` pre-session branch folds into `openWorkspace`, so `reuse === void 0` no longer short-circuits to `sessions.create({ workspaceId })`.

The plugin's decoration depends on exact text seams, so the gate was re-verified against the rc.3 artifact rather than assumed. All nine markers reach the derived source (`__dshGitWorktreeManagedGuard`, `dshGitWorktree.managed`, `dshGitWorktree.state.working`, `managedWorktreeDecoration`, `ManagedWorktreeIdentity`, `__dshGitWorktreeProtected`, `__dshGitWorktree`, `data-managed-worktree`). `visibleSessionMenuItems` is reported `MISS` on rc.3, but the same marker is also absent from the rc.2 artifact — its seam is `replaceIfPresent`, and the paired definition/usage needles match zero times on both generations, so the optional decoration is skipped identically on both. No decoration logic change was required.

The plugin does not call the changed signatures: `src/client/actions.ts:51` declares `create(input: { workspaceId: string; sessionId: string; agentPreset?: string }): Promise<string>`, and `agentPreset` continues to flow through the existing Host-default path.

## Residual risks

- The decoration path still relies on exact text seams in the official compiled Client. Each upstream bump requires re-running the version/SHA gate and the seam probe; a silent seam drift fails closed at build time, not at runtime.
- Compatibility was exercised on Windows only. The macOS-only cases (newline-in-path identity reads, executable-bit resource preservation) did not run here.
- Passing build and unit tests on rc.3 packages is source compatibility, not runtime acceptance on a launched Host.
